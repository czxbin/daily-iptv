# 每日直播源 · VLC 固定订阅

每天刷新公开社区目录，有限检查央视、卫视、港澳台及海外频道。只有取得媒体样本并用 FFmpeg **实际解出视频帧**的源才算本次通过。无需 Python 第三方库，不代理、不转播、不保存节目内容。

## 在 VLC 使用

首次 GitHub Actions 成功生成列表后，打开 VLC → 媒体 → 打开网络串流（macOS：文件 → 打开网络），粘贴：

https://raw.githubusercontent.com/czxbin/daily-iptv/main/public/live.m3u

把这个地址保存为书签；需要新列表时重新打开该地址。VLC 已载入的播放队列不会自动定时重新抓取 M3U。GitHub raw 有缓存，在国内的可达性也取决于网络。

分组地址只需把最后的文件名换成：
- `cctv.m3u`：央视
- `satellite.m3u`：卫视
- `hmt.m3u`：港澳台
- `international.m3u`：海外
- `other-chinese.m3u`：其他中文频道

[当前检测状态](public/STATUS.md) · [机器可读状态](public/status.json) · [本次逐源结果](public/results.json) · [运行记录](https://github.com/czxbin/daily-iptv/actions/workflows/daily.yml)

**没有首次通过检测的结果时，不生成假列表。** 公开源不保证 CCTV 1–17、省级卫视或所有海外频道齐全，不保证持续播放或画面对应标签。

## 每日自动运行

- 北京时间每天 **06:23**，对应 UTC 前一天 22:23。
- 支持 Actions → Refresh daily IPTV → Run workflow 手动刷新。
- 修改检测程序、测试、来源配置也会触发一次；自动生成文件的提交不会自我循环。
- 运行使用公开仓库的标准 Linux runner，无付费依赖、无额外云服务器。GitHub 免费配额、账户策略和服务条款仍适用，定时任务可能延迟或被 GitHub 暂停，不是准点 SLA。
- 探测阶段只有仓库只读权限，不持久保存 Git 凭证；独立发布阶段只提交 `public/`。
- 检测作业总上限 25 分钟，发布作业上限 5 分钟。并发任务排队，不同时改同一分支。检测固定读取当前 main；发布前核对同一提交基线，期间 main 改动则拒绝替换，避免旧任务覆盖新列表。推送不使用 force。

## 检测与范围

1. 每天重新读取 `config/sources.json` 中的中文及国家目录。
2. 去除重复 URL，按央视 / 卫视 / 港澳台 / 海外 / 其他中文分类。来源的频道 ID、地区、名称均为上游标签，未独立核实。
3. 每日最多 420 个候选、8 路并发、每频道最多两个变体，按日期轮转；这是有界目录刷新，**不是全网搜索，也不是每天穷尽全部源**。
4. 校验公网地址并将 TCP 连接固定到已校验 IP，TLS 仍验证原域名。重定向、HLS 子清单和分片每次都重新检查。DNS 独立子进程 3 秒超时，网络 socket 超时 5 秒（不是每个 HTTP 阶段的严格总时限），单源网络预算 18 秒；解码另有 6 秒探测 + 8 秒解码上限。整个单源探测另有独立子进程 35 秒硬上限（含慢 HTTP 头），批量检测 20 分钟后取消尚未开始的项。工作流提供最终总时限。
5. HLS 选择低带宽变体和近期完整片段，最多四层清单、三个重定向。清单最多 512 KiB，媒体分片最多 6 MiB，初始化段最多 512 KiB。FFmpeg 只读取本地临时媒体，并限制协议为 `file,pipe`。
6. HTTP 200、清单可读或单纯下载到字节都不算成功。必须探测到视频并解出至少一帧。加密、DRM、登录、带认证 URL、私网地址、非 HTTP(S)、VOD 和 byte-range HLS 默认跳过；部分本来可播放的源会因严格检测被排除。

默认目录均来自 [iptv-org/iptv](https://github.com/iptv-org/iptv)，包括中文、内地、港澳台、美国、英国、日本、韩国、法国、德国、加拿大、澳大利亚、新加坡分组。**它们共用一个上游，不是 14 个独立容灾来源。** 该项目代码/目录许可不等于电视内容的观看或转播许可。所有未独立确认的频道均标注授权未知。

检测位置是 GitHub runner，与你所在网络、地区不同。地区限制、时效签名、频道停播、源服务变更和网络波动都可能导致你无法播放。不会伪造 Referer、盗用登录态、破解 DRM 或绕过地域/付费限制。

## 失败保护与旧源

- 全部失败、超过半数来源目录失败，或通过总数跌至上一份的 30% 以下（上一份至少 10 条），保留上一份有效订阅。
- 单个分类全部失败，或通过数跌至该分类上一份的 30% 以下（上一份至少 5 条），只保留该分类上次有效文件，其他分类可继续更新。
- 合并订阅中的旧源标注“旧源，最后验证时间”；单独分类文件按原样保留，其生成时间在文件头，状态页同时注明可能过期。
- **保留不等于仍然可播**。`status.json` 的分类时效和 `STATUS.md` 是判断新鲜度的依据。
- 本次所有成功/失败及原因保存在 `results.json`，最近 30 次摘要在 `public/history/`。从未成功的分类显示暂无可用。

## 本地运行 / 修改来源

需要 Python 3.12 和 PATH 中的 FFmpeg / ffprobe：

```sh
python -m unittest discover -s tests -v
python -m iptv.runner
```

可用 `--config` / `--output` 指定路径。配置限制最多 20 个目录、总候选最多 420、最多 12 路并发。新增目录请先确认其来源和使用授权。直接 TCP + DNS 安全校验不走系统 HTTP 代理；限制直接 DNS/网络的环境会保守失败，而不是跳过校验。

退出码：0 本次有更新；2 本次整体保留上一份；1 程序/依赖错误。即使保留，工作流也先提交诊断，再标记异常。
